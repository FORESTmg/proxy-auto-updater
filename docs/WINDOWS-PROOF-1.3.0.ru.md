# Доказательства для Windows — сборка 1.3.0 (живой ПК <PC-NAME>)

Дата: 17.10.2026. Машина: <PC-NAME>, Windows 11, Ethernet <LAN-IP>.
Проверялось на живой установке `C:\Users\<user>\AppData\Local\ForestProxyUpdater`.

## 0. Что было сломано

`ui_helper._pid_alive()` считала процесс живым по успешному `OpenProcess`.
Успешный `OpenProcess` НЕ доказывает живость: он отвечает успехом и для
завершённого, ещё не освобождённого процесса. В `state/ui_helper.json` остался
pid 31800, процесса не было, а супервизор считал помощник работающим — поэтому
никогда его не поднимал и **значка в трее не было**.

Исправление (в исходниках `src/ui_helper.py`): `_pid_alive` = `OpenProcess` +
`WaitForSingleObject(h, 0)` (WAIT_TIMEOUT = жив, WAIT_OBJECT_0 = завершён);
добавлены `_pid_image()` и `_is_our_helper()` — пульс учитывается только если по
pid действительно работает НАШ файл помощника; `we_are_helper()` в сборке
требует ещё и имя своего файла (`forest-ui.exe`), иначе унаследованный признак
`FOREST_UI=1` делал «помощником» сам супервизор и он не поднимал настоящий.
