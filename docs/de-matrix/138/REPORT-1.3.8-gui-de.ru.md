## 1. Протокол — ФАКТ

Значок работает по **SNI (StatusNotifierItem + DBusMenu)**, XEmbed на этом
стенде не встретился ни разу:

| факт | значение |
|---|---|
| `_NET_SYSTEM_TRAY_S0` | `not found` (владельца нет) |
| `org.kde.StatusNotifierWatcher` | есть |
| `RegisteredStatusNotifierItems` | `[":1.16/StatusNotifierItem"]` — наш значок |
| `IsStatusNotifierHostRegistered` | `true` — хост (панель) есть |
| окна значка в X | нет; у процесса только `10x10` служебное и `3x3` selection-окно |

Тонкость, которую стоит знать при проверках: Qt регистрирует значок **без
well-known имени** — в `ListNames` нет `org.kde.StatusNotifierItem-<pid>-1`,
значок виден только как `:1.16/StatusNotifierItem` в
`RegisteredStatusNotifierItems` у watcher'а. Поэтому поиск «по имени сервиса»
(как в прежних скриптах) даёт ложное «значка нет»; проверять нужно свойство
watcher'а. Сырой вывод — `logs/protocol-sni.txt`.

Отсюда следствие: **меню и подсказку рисует панель** (Qt экспортирует `QMenu`
по DBusMenu, `forest_ui.py:_build_qt_menu`, в журнале `меню SNI собрано
(16 пунктов, подменю: фильтры/тема)`).

## 3. Дефекты и минимальные правки

### D1 (P0). Запасной значок откатывается: пользователь остаётся БЕЗ значка
Журнал (LXQt, реальная панель без лотка):
```
17:43:33 WARN штатного значка нет — … Свой значок: поднимаю
17:43:33 WARN режим значка переключён на «popup» (своё окно), старый значок снят
17:43:35 WARN режим значка переключён на «sni» (область уведомлений), старый значок снят
```
Местоположение значка по кадрам: t=4 с — `FOUND 1267 755`, t=6/8/11/14 с — `NOTFOUND`.
Причина: `Ui.refresh()` (тик 2 с) заново читает `ui.tray_mode` из настроек и
возвращает `sni`:
```python
# forest_ui.py, refresh()
want = self._mode_from_cfg()
cur = "own" if self.icon_mode == "popup" else "sni"
if self.has_tray and want != cur:
    self._apply_tray_mode(want)
```
`_ensure_visible_icon()` намеренно не пишет в настройки, поэтому «запасной» режим
живёт ровно один тик. Итог хуже, чем до 1.3.8: раньше был значок с «нет данных»,
теперь значка нет вообще.

**Правка (2 строки):** пометить режим как запасной и не переспрашивать настройку.
```python
# _ensure_visible_icon(), перед ui._apply_tray_mode("own"):
ui._tray_fallback = True
# refresh():
if (self.has_tray and not getattr(self, "_tray_fallback", False)
        and want != cur):
    self._apply_tray_mode(want)
```
(Альтернатива — при запасном режиме писать `ui.tray_mode="own"` только в
`self.cfg` в памяти, без сохранения на диск: `_set_tray_mode` не вызывать.)

### D2 (P0). Бандл не видит системную тему: `gsettings` отравлен `LD_LIBRARY_PATH`
Карточка светлая при ЛЮБОЙ теме DE. Но палитра работает: `FOREST_THEME=dark`
даёт `srgb(25,26,30)`, `FOREST_THEME=light` — `srgb(240,240,240)`. Значит
виновато определение, а не рисование. Замер:
```
$ gsettings get org.gnome.desktop.interface color-scheme            → 'prefer-dark'
$ LD_LIBRARY_PATH=/tmp/_MEI00000999CR0mOg gsettings get …           → 'default'
$ env -u LD_LIBRARY_PATH gsettings get …                           → 'prefer-dark'
```
Бандл ставит `LD_LIBRARY_PATH=/tmp/_MEI…` (проверено по `/proc/<pid>/environ`),
системный `gsettings` грузит из него glib и отвечает `default` — а `_detect_linux()`
трактует `default` как `light` (`theme.py`, строка `if "light" in scheme or
"default" in scheme: return "light"`). Это ровно та же болезнь, что чинили для KDE
в 1.3.8, только причина другая.

**Правка:** (1) не отдавать бандловые библиотеки системному процессу:
```python
env = {k: v for k, v in os.environ.items() if k != "LD_LIBRARY_PATH"}
r = subprocess.run(["gsettings", "get", ...], env=env, capture_output=True, text=True, timeout=3)
```
(2) `default` — это «нет предпочтения», а не «светлая»:
```python
if "dark" in scheme: return "dark"
if "light" in scheme: return "light"      # 'default' сюда больше не попадает
```
(3) без процесса: прочитать `~/.config/gtk-3.0/settings.ini`
(`gtk-application-prefer-dark-theme=1`) — работает и в бандле.

### D3 (P1). XFCE и LXQt не пишут `gsettings` — тему надо читать у них
`gsettings get … color-scheme` на XFCE = `'default'` всегда: XFCE хранит тему в
`xfconf` (`/Net/ThemeName`), LXQt — в `~/.config/lxqt/lxqt.conf`. Даже с
исправленным D2 карточка на тёмном XFCE останется светлой.

**Правка (5 строк, `theme._detect_linux`, до gsettings):**
```python
if "xfce" in os.environ.get("XDG_CURRENT_DESKTOP", "").lower():
    r = subprocess.run(["xfconf-query", "-c", "xsettings", "-p", "/Net/ThemeName"],
                       env=env, capture_output=True, text=True, timeout=3)
    if "dark" in (r.stdout or "").lower():
        return "dark"
```

### D4 (P2). Самотест противоречит коду 1.3.8 (3 проверки)
`--selftest` падает на утверждениях, которые 1.3.8 сама нарушила:
```
FAIL Linux/XEmbed: ПРАВЫЙ клик открывает НАШЕ меню … Context=0
FAIL QMenu трею не отдан (setContextMenu убран) — contextMenu=<QMenu …>
```
В SNI-режиме `_build_qt_menu()` **обязан** вызвать `setContextMenu`, иначе меню в
панели не будет; `Context` в SNI не приходит по протоколу. Проверки написаны под
XEmbed-путь, которого на живых панелях нет.

**Правка:** в самотесте ветвить по `ui.icon_mode`: для `sni` — проверять
`contextMenu is not None` и наличие `Menu` в SNI-свойствах; `Context`/XEmbed
проверять только для `icon_mode == "popup"`.

### D5 (P3). Отступ карточки не масштабируется (150 %)
При dpr 1.5 карточка 588×180 в (680,612): правый край 1268 (12 device px ≈ 8
логических — верно), а низ 792 → до края 8 device px = 5.3 логических вместо 14.
**Правка:** отступы карточки считать в логических пикселях и умножать на
`devicePixelRatio` при позиционировании.

### D6 (P3). `PANEL_PX = 46` захардкожен
`--tray-probe` всегда печатает `панель=46px`. Без панели (голый openbox) своё
окно встаёт с зазором 52 px от низа: `место=(1248,722)` при 1280×800. На панели
LXQt 32 px зазор тоже неверный.
**Правка:** брать высоту из `QScreen.availableGeometry()` (разница с `geometry()`),
`panel_px` оставить только как запасное значение.

| прогон | OK | FAIL | вердикт |

| `--selftest` с реальным X (xcb) | **150** | **10** | то же + 3 проверки, противоречащие SNI-коду (D4) |

Разбор падений:
* производительность Xvfb: «худший интервал кадра 60.4 мс < 34», «пропущено 6 из 8
  кадров», «в покое процессор 547 мс за 3 с», «пиксели полосы: 3 разных» — llvmpipe,
  не код;
* ширина меню `301 px` вместо `269` — метрики DejaVu вместо Segoe UI (артефакт
  стенда, зафиксирован ещё в 1.3.2);
* «сбой показа меню записан в журнал» — проверка читает `main.log` корня
  `FOREST_ROOT`, строка пишется в лог каталога состояния (артефакт стенда, 1.3.2);
* «демо-данные: 1/100000» (только xcb) — данные демо-режима не успевают заполниться
  за прогон;
* D4 — три проверки ниже.

Эталон: двоичный `forest-ui` из `forest-proxy-updater-1.3.7-1-x86_64.pkg.tar.zst`
извлечь не удалось — в стенде нет `zstd`, а ставить пакет без sudo нельзя. Сравнение
с опубликованным эталоном (`docs/RELEASE-NOTES-1.3.2.md`: **158 OK / 0 провалов по
существу**, 2 артефакта стенда): новых падений **кода** нет, но появились 3
расхождения теста с кодом 1.3.8 (D4).

## 5. Что НЕ проверено и почему

* **Cinnamon** — 531 пакет, не «легко» (замер `apt-get -s`).
* **«Скрытые» (overflow)** — у XFCE/MATE systray нет корзины скрытых; это
  свойство панели, а не приложения. У Cinnamon есть — но он не ставился.
* **MATE SNI-меню/подсказка** — в прогоне факта applet `notification-area` не поднял
  watcher (`Requested out-of-process applet, which is only supported on X11`), поэтому
  проверялся только запасной путь.
* **DE целиком на 150 %** — масштабировался только Qt-клиент (`QT_SCALE_FACTOR=1.5`,
  `Xft.dpi=144`); GTK-панель осталась 27 px, потому что `GDK_SCALE` не выставлялся.
  Проверено «наше» поведение при dpr 1.5, а не весь рабочий стол.
* **KDE Plasma** — не входило в задание (проверялось в 1.3.7/1.3.8 живым прогоном).
